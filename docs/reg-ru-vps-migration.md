# План переноса ПОСЛЕ на VPS Reg.ru

## Цель

Развернуть текущий Node.js-сервис на VPS Reg.ru без потери клиентов, питомцев, визитов, администраторских учётных записей и интеграции YClients.

## Предварительно согласованная инфраструктура

| Компонент | Решение |
|---|---|
| VPS | Reg.Cloud Std C2-M2-D40: 2 vCPU, 2 ГБ RAM, 40 ГБ SSD |
| ОС | Ubuntu 24.04 LTS |
| Веб-сервер | Nginx с HTTPS и обратным проксированием на Node.js |
| Приложение | Production build из `dist/`, управляемый systemd |
| База данных | MySQL на VPS с экспортом и восстановлением всех существующих таблиц |
| Домены | `posle-grooming.ru` и `www.posle-grooming.ru` |

## Порядок работ

1. Создать VPS и сохранить IP-адрес, пароль root или SSH-ключ.
2. Настроить базовую защиту: обновления ОС, отдельного пользователя, SSH-ключи и firewall.
3. Установить Node.js LTS, pnpm, Nginx, MySQL и Certbot.
4. Подготовить адаптацию приложения для самостоятельного запуска: заменить зависящие от Manus OAuth и файлового хранилища компоненты, сохранив клиентский вход и административную модель.
5. Создать дамп таблиц клиентов, питомцев, визитов, сессий и учётных записей; проверить его до и после восстановления на VPS.
6. Перенести переменные окружения: SMTP, YClients, секрет сессий и параметры базы данных. Секреты не хранятся в репозитории.
7. Загрузить production build, настроить systemd и Nginx.
8. Выпустить Let’s Encrypt сертификаты для корневого домена и `www`.
9. Переключить DNS только после успешной проверки по временному адресу или hosts-записи.
10. Проверить публичные страницы, вход клиента, личный кабинет, администраторский вход, YClients, отправку кодов и загрузку фотографий.

## Условия безопасного переключения

Не отменять текущий Host-0 и не менять DNS до резервной копии базы, успешного восстановления на VPS и прохождения контрольного списка. Откат выполняется возвратом прежних DNS-записей до окончания окна проверки.
